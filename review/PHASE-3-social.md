# Phase 3: Friends, chat, notifications, presence

Scope: `backend/backend/friends/*`, `chat/*`, `api/consumer.py`, WS routing files.

| Location | Severity | Problem | Fix |
|---|---|---|---|
| `chat/consumers.py:29-37` + `frontend/static/js/components/ChatBox.js:80,125-129` | critical | Server broadcasts the raw client JSON. The client sets `author: window.user.username`, so any user can send messages as someone else. `content` is then rendered with `innerHTML` -> stored XSS in the friend's browser. With XSS the attacker can call `settings/update/` (no current password, Phase 2) = account takeover. | Build the outgoing event on the server: `{"author": self.scope["user"].username, "content": str(content)[:1000], "timestamp": ...}`. Frontend: render with `textContent`. |
| `chat/consumers.py:16-23`, `chat/views.py:8-19` | high | No membership check. The room is whatever string is in the URL. Any logged-in user who knows a friendship UUID can join the WS room and read history via `GET /api/chat/messages/<uuid>/`. | Resolve the conversation to a `Friendship` by uuid, check `request.user` is `source_user` or `target_user` and status is `accepted`. Close with 4003 otherwise. Same check in REST view. |
| `chat/consumers.py` | high | Blocking does not stop chat. Friendship uuid stays the same after block, so the blocked user can keep sending messages. | Same membership check: reject when status is `blocked`, check on every `receive` (or on block, push a close to the room). |
| `friends/views.py:192-212` | high | `accept_friend_request` does not check `status == "pending"`. If A sent a request to B and later A blocked B, B can call accept and the block is gone. | Filter `status=Friendship.PENDING`. |
| `friends/views.py:239-267` | high | `update_friendship_status` lets either side set any status. A blocked user can set `accepted` and escape the block. The sender can set `accepted` on their own pending request (forced friendship). | Allow only valid transitions: target may accept/reject a pending request; only `blocked_by` may unblock. Or remove this endpoint (accept/block/unblock already exist). |
| `friends/views.py:270-288` | med | `friend_id` is a `User` instance (PrimaryKeyRelatedField). `Notification.objects.create(user_id=friend_id)` raises `TypeError`, and `f"user_{friend_id}"` becomes `user_<username>`, so the notification goes nowhere. | Use `friend_id.id` (rename the field to `friend`). |
| `chat/consumers.py:29-43` | med | No validation: bad JSON or missing `content` raises and kills the socket. No length limit on content. Message is broadcast before it is saved, so a DB error still shows the message. | `try/except json.JSONDecodeError`, check type and length, save first then broadcast. |
| `api/consumer.py:9-31,73-77` | med | `FriendsStatusConsumer` and `NotificationConusmer` never check `is_anonymous`. Anonymous sockets get the full online user list; their id is `None` and `"None"` is added to the online set. | Close with 4001 when `self.scope["user"].is_anonymous`. |
| `api/consumer.py:14-18` | med | Sync `redis.Redis` calls inside async consumer block the event loop (and the game loops in the same process). Host/port hardcoded (`6379`), ignores `REDIS_PORT`. | Use `redis.asyncio`, read host/port from env. |
| `api/consumer.py:18,33` | med | Online set is per user id, not per connection. Two tabs open, close one: user shows offline. After a crash/restart, stale ids stay in the set forever. | Use a counter per user (`HINCRBY`) or a set of channel names per user, with a TTL/heartbeat. Clear on startup. |
| `api/consumer.py:20-29` | low | Every connect/disconnect sends the full online list to every user (O(n^2) traffic). | Send only the delta; full list only to the new socket. |
| `friends/views.py:134-166` | low | Exists-then-create race. Two users sending each other a request at the same time creates two rows (A->B and B->A); later `.first()` picks one at random. | DB constraint on the unordered pair (`least/greatest` UniqueConstraint), or always store the lower id as `source_user`. |
| `friends/views.py:144-162` | low | A rejected request blocks any new request forever ("Friendship already exists"). | Allow re-send when status is `rejected` (update the row). |
| `friends/views.py:381` | low | Unblock deletes the row, so a previous friendship is lost. Design choice; document it. | Keep, or restore previous status. |
| `friends/views.py:54-131` | low | List views: 4 copies of the same user/friend swap loop; N+1 queries (each `UserSerializer` loads profile). `FriendshipSerializer` returns the target's email to any sender. | One helper, `select_related("source_user__profile", "target_user__profile")`, public user serializer without email. |
| `chat/consumers.py:20-23` | low | `group_add` + `accept` run before the anonymous check. | Check auth first, then accept. |
| `chat/consumers.py:27` | low | `disconnect` calls `self.close()` on an already closed socket. | Remove. |
| `chat/views.py:14-15` | low | Broad `except` returns `str(e)`. No pagination on history. | Remove except; paginate (last 50). |
| `chat/templates/`, `backend/backend/static/` | low | Leftover test login/chat pages (Bootstrap CDN). Not routed. | Delete. |
