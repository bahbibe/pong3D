# Phase 4: Game, tournament, matchmaking

Scope: `backend/backend/game/game_manager.py`, `game/consumers.py`, `game/views.py`, `game/serializers.py`, `game/models.py`, `matchmaking/consumers.py`.

| Location | Severity | Problem | Fix |
|---|---|---|---|
| `matchmaking/consumers.py:50` | critical | `int(self.opponent_id[0])` takes the first character of the id string (redis returns `"12"`). Any queued user with id >= 10 is replaced by user 1-9 in the created game. The real opponent gets the game id but is rejected by `GameConsumer.get_game` (not a player). | `int(self.opponent_id)`. |
| `game/game_manager.py:39-45` | critical (verify at runtime) | `GameInstance.game_loop` reads `self.player.username`, which only exists on `BotInstance`. `reset_pause` is `True` at start, so the first tick raises `AttributeError` and the task dies silently (exception never retrieved). Remote games then get no state updates. Copy-paste from the bot loop. | Send to `self.game_id`, not `f"{self.player.username}_bot"`. Add a done-callback that logs task exceptions. |
| `game/game_manager.py:27,167` + `consumers.py:98-101,325-328`, `game_manager.py:144-146,291-294` | high | Game/bot tasks never stop. `running` is never set to `False`; `remove_*_instance` only deletes the dict entry. On disconnect the game is paused, and a paused loop sends a message every second forever. Every bot game and every abandoned remote game leaks a task. | On remove: `instance.running = False; instance.game_loop_task.cancel()`. Add an abandon timeout (e.g. both players gone 30 s -> forfeit/end). |
| `game/consumers.py:318-323` | high | `get_bot_instance(self.user.id)` passes an `int`, but the dict is keyed by `str`. Lookup always misses, so each connect creates a new `BotInstance` and overwrites the old one, whose loop keeps running (see leak above). | Use `str(self.user.id)` everywhere, or key by int. |
| `game/consumers.py:113-124`, `341-347` | high | Paddle movement is applied once per client message, with no limit. A client can send hundreds of `left`/`right` messages per tick and teleport the paddle. | Client sends key state (`{"dir": -1/0/1}`); server stores it and moves the paddle a fixed step per tick in the game loop. |
| `game/game_manager.py:57,75-77` | high | `save_game()` writes the full `Game` row every tick (60 writes/s per game) and saves all fields, so it can overwrite `player1`/`player2` set elsewhere (e.g. `qualify_next_round`). | Save only on score change: `save(update_fields=["player1_score", "player2_score"])`. |
| `game/models.py:6-12` + `game/views.py:27-120`, `api/views.py:106-115` | high | `Game` has no status/finished/created_at field. Filter stats on finished games. Refuse to start finished games. |
| `game/consumers.py:126-137` | med | Dead `game_update` branch uses undefined `self.game_group_name` and `self.update_game_state`, and would broadcast client-supplied state. A client sending `type: game_update` crashes the consumer. | Delete the branch. |
| `game/consumers.py:104-106`, `333-334` | med | `json.loads` / `['type']` without checks. Bad input kills the socket. `int(self.game_id)` on a non-numeric id raises inside `get_game` (`\w+` allows letters). | Validate input; route regex `\d+`. |
| `game/consumers.py:155-197` | med | Tournament qualification runs only in the winner's consumer at game end. If the winner is disconnected at that moment, the final is never filled and the tournament is stuck. Broad `except` + `print` hides failures. | Do qualification once, server-side, in the game loop end handler (not per consumer). Log exceptions. |
| `game/consumers.py:203-260`, `285-302` | med | `TournamentConsumer`: no auth check (anonymous user makes `Q(game__player1=AnonymousUser)` raise). Create bracket games in `create_tournament` inside `transaction.atomic()`. Use `select_for_update()` when taking a seat. |
| `game/models.py:16-18`, `20-26` | med | `Tournament.finished` is never set; `Tournament_Participants` is never used. Tournament list grows forever with dead tournaments. | Set `finished` when the final ends; filter list on `finished=False`; drop or use `Tournament_Participants`. |
| `game/views.py:123-137`, `182-260` | med | State-changing endpoints use GET (`create_tournament`, `invite_friend`, `play_again`). With `SameSite=Lax` (browser default) the cookie is sent on top-level GET navigation, so a link can trigger them (CSRF). No limit on invites. | Make them POST. |
| `game/views.py:188-189` | med | `invite_friend` only checks `blocked_by=None`, not `status="accepted"`.
